## 3. 问题根因

共 200 次工具调用，失败 5 次（Leader 2、后端 1、前端 1、测试 1）。比失败更贵的是**平台缺陷引出的绕行**（3.A）和**“成功但无效”的调用**（3.D）。

### A. 平台缺陷

#### A1. Leader 回合结束时杀掉项目根的保留服务（P0，本次引入的回归）

- `relaunch()` 在 `active_workspace = 项目根` 的上下文里启动新进程，所以新 Job 的 `workspace` 就是项目根。
- Leader 的回合在 `team.py:292` 的 `finally` 里执行 `await processes.close(workspace=workspace_root().resolve())`。Leader 的 `workspace_root()` 也是项目根，且调用时**没有** `keep_services=True`。于是**所有已移到项目根的保留服务，在下一次 Leader 回合结束时被杀**。
- 本次 3 次全部命中：

| 服务 | 移到项目根（审核记录） | Leader 回合结束 | 后果 |
| --- | --- | --- | --- |
| frontend-preview:8101 | 02:26:50 | 02:27:40 | 被杀（本来也不该保留，见 A5） |
| hello-world:8100（后端交付） | 02:37:14 | 02:37:53 | 测试 02:39:36 发现无监听，自己在快照里重启 |
| hello-world:8100（测试交付） | 02:50:37 | 02:52:34 | **交给用户的服务被杀**；Leader 最后一句“服务运行中”与事实不符 |

- 上一次（HW2）测试保留的服务还在测试快照里（workspace ≠ 项目根），没有被这行代码波及，所以存活了下来。是 `532d1b2` 把服务移到项目根以后，`399d191` 就有的这段 Leader 清理才开始杀它们。
- 量化：测试的探测 + 恢复约 3 次调用、0.05M；更大的代价是交付状态错误，以及 3.D 中被改写的证据。
- 修复：`team.py:292` 改为 `close(..., keep_services=True)`（Leader 本身不启动命令，或只关闭非 keep 的 Job）；补一条测试：“项目根的保留服务在 Leader 回合结束后仍在运行”。

#### A2. 开发任务进行中，快照里的服务被标 STALE，平台指引“stale 就重启”在这里无效（P0）

  - 自测从 14 项扩到 24 项（新增“服务启动后新增静态文件立即可访问”等）；
  - 给 Leader 和测试各写一条 1K 字说明“GET / 需服务从项目根启动”。

#### A3. fold 占位符被模型当成参数模仿，源码被覆盖（P1）

#### A6. 本地回环的监听/连接也需要 `network=true`，环境说明没写（P2）

## 8. 代码质量

**评分：正确性 8 / 10，与需求的匹配度 6.5 / 10（上次 9 / 8）。**

做得好的地方：
- 架构延续上次：单个标准库 Python 服务同时提供 `/api/hello` 和静态页面，同源、无构建、零第三方依赖，一条命令启动。
- 前端：见 5 节。`fetch` 失败、非 2xx、缺少 `message` 分别处理，错误态有重试。
- 后端：统一 JSON 错误结构、`Content-Length` 正确、路径穿越防护（`relative_to`）。

问题：
1. **静态目录解析依赖启动目录**（A2 的直接产物）：`static_dir()` 每次请求先看 `Path.cwd() / "frontend"`，存在就用它。从一个恰好有 `frontend/` 的其他目录启动，会静默托管另一套页面。最初版本只用 `Path(__file__).parent.parent / "frontend"`，那才是正确且更简单的写法。
2. **为行数删功能**：HEAD 支持被删除，现在 HEAD 请求会得到 `BaseHTTPRequestHandler` 默认的 501（非 JSON）；契约为此改到 v3。
3. `_selftest.py` 为凑行数压缩了格式（一行 import 多个模块、7 行超过 110 字符）。
4. 对 Hello World 仍偏重：133 行中大部分是手写静态服务；`SimpleHTTPRequestHandler(directory=…)` 加一个 `/api/hello` 分支约 25～30 行即可。
5. README 的错误陈述与自相矛盾（6.2）。
6. **交付的服务没有在运行**（A1）——这不是代码问题，但用户按 Leader 的答复打开 8100 会失败。

## 9. 其他影响建站效率的因素

1. **“允许所有操作”**：02:20:56 起开启，61 次审核中 59 次直接放行。人工审批数（1）与上次（2）不可比；上次的 P1“本任务创建的文件直接放行”也因此无法验证。

4. **所有调用都用 `qwen3.8-max`**；`WDRUNGE_MODEL_SMALL_TASKS` 仍未配置。
