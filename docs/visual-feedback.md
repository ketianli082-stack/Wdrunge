# 网站预览与点选、框选修改

基线：`origin/context-desk` 的 `5de5b72`。功能分支：`feature/visual-feedback-zlj`。

## 使用

1. 启动 Wdrunge 前后端，在项目中打开一段对话。请先让团队启动生成网站的开发服务。
2. 在办公室右上角点击「网站预览」，输入实际本机 HTTP 地址并打开。右侧群聊保留。
3. 展开「接入选择脚本」，点击「让 Agent 接入」。请求会通过现有聊天接口交给 Leader，修改项目的开发入口。也可手动添加显示的 script 标签。只有实际接入并刷新成功后才显示「已连接」。
4. 点击「选择修改位置」，悬停高亮，点击单选，拖动直接框选，不需要切换工具。鼠标移动不足 6 像素按点击处理，避免轻微手抖变成框选。直接点击另一个元素可以替换选择，再点击已选元素可以取消；按住 Shift 点击或拖动可以追加选择。需要改整张卡片时点击「选择父级区域」。Esc 清空并退出选择；切换「浏览网页」后可以正常操作按钮和链接。
5. 输入「文字改成蓝色并加粗」，或「点击这个按钮后保存文章到数据库」，发送修改要求。Leader 继续使用现有分工、文件工具、交付和测试流程。修改成功后由开发服务器热更新，或手动点击刷新。

## 实现

- `frontend/public/visual-inspector.js` 在目标网站内部读取 DOM，通过 `postMessage` 与预览面板通信。脚本从 Wdrunge UI 服务加载，不经过模型，不安装浏览器插件。
- `WebsitePreview.tsx` 显示 iframe、连接状态和批注。父子窗口验证来源窗口、origin、每次加载的随机 token 和文档 pageId；刷新会丢弃旧选择并重新连接。
- 收集当前路由、元素标签、有限文字、CSS selector、关键计算样式、视口位置、父级摘要，以及可选的 `data-wdrunge-source`。不采集表单值、cookies、存储或整份 HTML。
- `visualFeedback.ts` 校验和限制观察数据，再与用户要求一起构建消息。页面文字标记为不可信观察信息；源码标记只是线索。
- `App.tsx` 将批注提交到已有 `sendContent → streamConversationMessage`。因此消息、执行状态、SSE、错误和会话存储沿用已有逻辑，批注文本会随普通用户消息持久化。暂不需要数据库迁移。
- Agent 使用 selector、文字和可选源码位置定位组件，读取真实源码后通过 `write_project_file` 修改；全栈需求沿现有 Leader 分工执行，验证由现有 `browser_verify` 完成。浏览器本身不会直接编辑磁盘。

## 选择方式如何配合

- 点选：适合一个标题、按钮、输入框。普通点击替换，Shift 点击多选，列表中的 × 单独移除。
- 父级：适合整张卡片、导航栏等共同容器；一次选择一个父级，可以继续向上选择。
- 框选：适合一组相邻内容。优先收集框内完整包含的上层 DOM 元素，避免同一卡片的每个子节点都重复提交。框选坐标也会保留，共同祖先只用于定位，不代表用户要求修改整个祖先。
- 全站或业务修改：不必框出所有页面。选一个代表位置，说明「所有同类按钮统一」「点击后保存数据库」等范围，再由 Leader 分工。选区提供位置，用户文字决定需求，不把后端需求限制成 CSS 修改。

最多选择 20 个元素，框选最多扫描 10000 个 DOM 节点，达到上限会提示。空白/部分覆盖区域可能只有坐标，没有完整元素；这不是截图视觉理解，应扩大框选或点选附近元素。消息超过安全长度时要求缩小范围，不静默丢弃元素。

## 页面变化与新鲜度

选择保存的是当前文档中的 DOM 引用，不是永远不变的 selector。MutationObserver 监听内容和属性变化，滚动/缩放和周期检查更新位置、文字与计算样式。发送前再次请求当前快照；失败时不发送旧数据。元素被框架删除或替换后，旧选择会移除，需要重新选择，不猜测哪个新元素等价。

SPA 的 pushState、replaceState、popstate、hashchange 会清除旧选择并同步地址。完整页面加载会换文档标识、重新握手；新页面也必须加载选择脚本。同源跳转支持自动重连；跳转到其他 origin（包括不同端口）不会沿用旧信任关系，需要在地址栏明确打开新地址并重新接入。心跳丢失会禁用选择并提示，不假装仍然连接。

区域坐标表示文档位置，不是永久绑定的一组元素；页面布局大幅变化时建议重新框选。发送快照后页面仍可能变化，所以 Agent 必须读取实际源码并核实，而不是把观测数据当成绝对事实。

## 群聊为何可能仍显示处理中

文件已经修改、开发服务器已经热更新，不代表平台任务已经完成验收。实际排查发现任务停在 review，Leader 口头汇报完成后，过几分钟才正式验收。

执行状态接口现在额外返回 task_states 和 leader_running。UI 分别显示执行、待验收、阻塞、排队、Leader 处理或同步状态；保留原有停止任务语义。Leader 提示词要求按交付证据调用正式验收工具，再汇报完成。不能因网页变化或一句“完成”直接自动验收；提示词能改善流程，但不保证模型每次都正确调用工具。

## 边界与后续

本版是本机项目预览器，支持 HTTP 的 localhost、127.0.0.1、IPv6 loopback。不是任意外网站点的完整浏览器。需要目标网站主动接入脚本；不绕过浏览器同源策略或 CSP。网站禁止 iframe 嵌入、脚本被 CSP 阻止、Wdrunge UI 服务关闭时需相应调整开发配置。生产构建应移除本机脚本。

目前支持点选、多选、逐级父元素和拖动框选。不支持 Shadow DOM 内部、子 iframe、伪元素和画布内部选择。框选不是截图分割，不保证准确理解纯图片中的位置。源码标记可手动提供，尚无自动 Vite/Babel 插件。selector 和源码标记都可能过时，Agent 必须核实；共享组件修改可能影响多个实例。

自动代码修改效果取决于模型配置、任务调度、项目和服务状态。用户已验证初版真实模型可修改标题颜色和字重；本次增量的自动化测试以假回调和模拟后端验证交互及请求，不调用收费模型，不宣称已完成新版真实模型端到端验证。

## 验证

`npm.cmd run build` 检查 TypeScript 并构建。启动 `npm.cmd run dev -- --host 127.0.0.1` 后，用已安装 Playwright 的环境运行 `node scripts/visual-feedback.test.mjs`。可设置 `WDRUNGE_PLAYWRIGHT_MODULE` 指向已有的 Playwright 包，`WDRUNGE_TEST_UI` 指定 UI 地址，`WDRUNGE_TEST_BROWSER=msedge` 使用本机 Edge 的独立测试会话。

浏览器测试使用另一端口的测试网站，覆盖跨源连接、点选不触发按钮、退出后正常点击、父级选择、敏感输入排除、需求传递、刷新、Esc、未接入提示、地址/消息校验、连续点选、再次点击取消、Shift 多选、列表移除、DOM 更新与删除、SPA/完整页面导航、心跳不覆盖输入、拖动框选，以及模拟真实 App 的待验收/空闲状态。后端 `tests/test_conversation_execution.py` 覆盖 review 仍为未验收、停止后状态归零。开发演示入口是 `/dev/visual-feedback.html`，不会进入生产构建。

更新后请重启后端以加载新增状态字段和 Leader 提示词，刷新 Wdrunge 前端，并刷新预览网站以加载新版选择脚本。已运行中的模型上下文未必立即重读提示词，建议新建一次测试对话。
