## 一、项目概述

### 1.1 产品定位

一款面向个人创作者的**轻量级独立博客系统**，强调内容表达与阅读体验，帮助博主建立自己的数字花园。不做社交分发，不做流量焦虑，回归写作的本质——**让好内容被看见**。

### 1.2 目标用户

| 角色 | 画像 | 核心诉求 |
|------|------|----------|
| **博主（管理员）** | 技术/设计/产品从业者，有一定技术背景，追求个人品牌沉淀 | 专注写作、低维护成本、掌控自己的内容 |
| **访客** | 通过搜索引擎、社交链接、RSS 订阅进入的读者 | 流畅阅读、快速找到感兴趣的内容 |

### 1.3 竞品参考

- **WordPress**：功能大而全但笨重，个人博客不需要那些复杂度
- **Hexo/Hugo**：静态博客需要命令行操作，非技术用户不友好
- **Notion/Super**：依赖第三方平台，数据不在自己手里
- **本产品的差异化**：开箱即用 + 自托管 + 所见即所得编辑 + 数据完全自主

### M1. 文章管理（CRUD）— P0

**功能描述**：博主可以对文章进行完整的生命周期管理。

**详细需求**：

| 功能点 | 说明 |
|--------|------|
| 创建文章 | 标题、正文（Markdown）、摘要、封面图、分类、标签、SEO 描述 |
| 编辑文章 | 编辑已发布或草稿状态的文章，保留修改历史（V1 不做版本对比） |
| 发布/下线 | 文章有「草稿」和「已发布」两种状态，支持一键切换 |
| 删除文章 | 软删除，管理员可恢复 |
| 置顶文章 | 置顶文章在列表顶部展示 |
| 定时发布 | 设定发布时间，到点自动发布（P2，V1 不做） |

**验收标准**：

- [ ] AC-1.1：博主创建文章后，文章默认状态为「草稿」，前台不可见
- [ ] AC-1.2：文章发布后，立即出现在首页文章列表和对应分类/标签页
- [ ] AC-1.3：文章删除后从所有列表和搜索中消失，但数据库中保留
- [ ] AC-1.4：置顶文章始终排在列表第一位，多篇置顶按发布时间倒序

### M2. Markdown 编辑器 — P0

**功能描述**：博主使用 Markdown 编写文章正文，支持实时预览。

**详细需求**：

| 功能点 | 说明 |
|--------|------|
| Markdown 语法 | 支持标准 CommonMark + GFM 扩展（表格、任务列表、代码块） |
| 实时预览 | 左右分栏，编辑区修改后预览区实时更新 |
| 代码高亮 | 代码块支持语法高亮（主流编程语言） |
| 自动保存 | 编辑过程中每 30 秒自动保存草稿 |
| 图片插入 | 支持粘贴上传、拖拽上传图片，自动插入 Markdown 图片语法 |
| 快捷工具栏 | 常用格式（加粗、斜体、链接、图片、标题等）的快捷按钮 |

**验收标准**：

- [ ] AC-2.1：编辑器支持标准 Markdown 语法，预览渲染正确
- [ ] AC-2.2：粘贴一张截图，自动上传并在编辑器中插入图片链接
- [ ] AC-2.3：页面意外刷新后，自动保存的草稿内容不丢失

### M3. 分类与标签 — P0

**功能描述**：通过分类和标签两个维度组织文章。

| 维度 | 规则 |
|------|------|
| 分类（Category） | 每篇文章**必选一个**分类，分类支持层级（最多两级） |
| 标签（Tag） | 每篇文章**可选多个**标签，标签为扁平结构，自由创建 |

**验收标准**：

- [ ] AC-3.1：创建分类时可指定父分类，形成两级结构
- [ ] AC-3.2：点击某个分类，展示该分类下所有文章（含子分类）
- [ ] AC-3.3：点击某个标签，展示含该标签的所有文章
- [ ] AC-3.4：分类和标签页面均支持分页

### M4. 首页与文章列表 — P0

**功能描述**：博客首页，访客进入的第一个页面。

**页面结构**：

```
┌──────────────────────────────────────┐
│  Header：站名 + 导航栏 + 搜索入口     │
├──────────────────────────────────────┤
│  Hero 区（可选）：博主一句话介绍       │
├──────────────────────────────────────┤
│  文章列表（卡片/列表形式）             │
│  - 封面图 + 标题 + 摘要 + 日期 + 分类 │
│  - 置顶文章带标识                     │
│  - 底部分页器                         │
├──────────────────────────────────────┤
│  Footer：版权 + 社交链接 + RSS 入口   │
└──────────────────────────────────────┘
```

**验收标准**：

- [ ] AC-4.1：首页默认按发布时间倒序展示已发布文章
- [ ] AC-4.2：每页展示 10 篇文章，支持分页导航
- [ ] AC-4.3：文章卡片展示封面图、标题、摘要、发布日期、分类名
- [ ] AC-4.4：首屏加载时间 ≤ 1.5s（Lighthouse Performance ≥ 90）

### M5. 文章详情页 — P0

**功能描述**：文章正文阅读页面，核心阅读体验。

**详细需求**：

| 功能点 | 说明 |
|--------|------|
| 正文渲染 | Markdown 渲染为 HTML，排版清晰、可读性高 |
| 目录导航（TOC） | 根据 H2/H3 自动生成侧边目录，点击跳转 |
| 文章元信息 | 标题、发布日期、分类、标签、阅读时长预估 |
| 上/下篇导航 | 文章底部展示前一篇和后一篇文章的链接 |
| 代码块增强 | 代码块支持一键复制 |
| 图片灯箱 | 点击图片放大查看 |

**验收标准**：

- [ ] AC-5.1：正文排版字体、行距、段距在主流分辨率下阅读舒适
- [ ] AC-5.2：TOC 目录随滚动高亮当前章节
- [ ] AC-5.3：代码块右上角有复制按钮，点击后显示「已复制」反馈
- [ ] AC-5.4：上/下篇导航仅展示同分类或全局的相邻文章（按发布时间）

### M6. 评论系统 — P1

**功能描述**：访客可对已发布文章进行评论。

**详细需求**：

| 功能点 | 说明 |
|--------|------|
| 匿名评论 | 填写昵称 + 邮箱（可选）即可评论，无需注册 |
| 评论审核 | 博主可设置评论是否需要审核后展示 |
| 评论管理 | 博主可删除、标记垃圾评论 |
| 回复评论 | 支持一级嵌套回复（不做多层嵌套） |
| Markdown 支持 | 评论支持有限的 Markdown 语法（加粗、链接、代码） |

**验收标准**：

- [ ] AC-6.1：评论提交后，若开启审核则显示「等待审核」提示，不对外可见
- [ ] AC-6.2：博主在后台可批量审核通过/拒绝评论
- [ ] AC-6.3：评论内容做 XSS 过滤，防止注入攻击

### M7. 全站搜索 — P1

**功能描述**：访客通过关键词搜索文章。

**详细需求**：

| 功能点 | 说明 |
|--------|------|
| 搜索范围 | 标题 + 正文 + 标签 |
| 搜索方式 | 前端全文索引（如 Fuse.js），适合中小博客 |
| 结果展示 | 匹配关键词高亮，展示标题 + 摘要片段 |
| 即时搜索 | 输入时实时返回结果（防抖 300ms） |

**验收标准**：

- [ ] AC-7.1：搜索响应时间 ≤ 200ms（100 篇文章以内）
- [ ] AC-7.2：搜索结果高亮匹配关键词
- [ ] AC-7.3：搜索索引在新文章发布后 5 分钟内更新

## 五、非功能性需求

### 5.1 性能

| 指标 | 目标值 |
|------|--------|
| 首屏加载（FCP） | ≤ 1.2s |
| 最大内容绘制（LCP） | ≤ 2.0s |
| 交互延迟（FID） | ≤ 100ms |
| API 响应时间（P95） | ≤ 300ms |
| Lighthouse Performance | ≥ 90 |

**实现建议**：SSR 或 SSG（静态生成）优先；图片懒加载 + WebP；静态资源 CDN；文章列表接口缓存。

### 5.2 SEO

- 每个页面有独立的 `<title>` 和 `<meta description>`
- 文章页使用语义化 HTML（`<article>`, `<h1>`~`<h6>`）
- 自动生成 `sitemap.xml`
- URL 使用可读 slug（如 `/post/my-first-blog-post`）
- 支持 Open Graph / Twitter Card 元标签
- 图片有 `alt` 属性

### 5.3 响应式设计

| 断点 | 宽度 | 适配策略 |
|------|------|----------|
| Mobile | < 768px | 单栏布局，汉堡菜单，TOC 隐藏 |
| Tablet | 768px ~ 1024px | 双栏布局 |
| Desktop | > 1024px | 三栏布局（目录 + 正文 + 侧栏） |

### 5.4 安全

- 评论内容 XSS 过滤
- API 接口 JWT 鉴权 + RBAC
- 图片上传限制文件类型和大小（≤ 5MB，jpg/png/gif/webp）
- HTTPS 强制
- 关键操作日志记录

### 5.5 可访问性（A11y）

- 键盘可导航
- 图片 alt 文本
- 颜色对比度 ≥ WCAG AA 标准

### 5.6 国际化（V1 不做）

V1 仅支持中文，但数据层预留 i18n 扩展能力（如多语言字段）。

## 六、数据模型概要

供后端参考的核心实体：

```
User (博主)
├── id, username, password_hash, display_name, avatar, bio
├── social_links (JSON), created_at

Post (文章)
├── id, title, slug, content (Markdown), summary
├── cover_image, status (draft/published), is_pinned
├── category_id, created_at, updated_at, published_at
├── seo_title, seo_description
├── view_count, estimated_reading_time

Category (分类)
├── id, name, slug, parent_id, sort_order

Tag (标签)
├── id, name, slug

PostTag (多对多)
├── post_id, tag_id

Comment (评论)
├── id, post_id, parent_id, author_name, author_email
├── content, status (pending/approved/spam), created_at

Media (媒体)
├── id, filename, url, mime_type, size, uploaded_at

SiteConfig (站点配置)
├── key, value (JSON) — 站名、描述、About 内容、社交链接等

FriendLink (友链)
├── id, name, url, description, avatar, sort_order
```

### 需后端确认的技术决策

1. **SSR vs SSG vs CSR**：影响 SEO 方案和部署方式，建议前端同学评估后给出结论
2. **图片存储**：本地文件系统 vs OSS（阿里云/Cloudflare R2），影响部署复杂度
3. **搜索引擎**：前端全文索引（Fuse.js）vs 后端搜索（SQLite FTS5 / PostgreSQL full-text），取决于文章量级
4. **评论反垃圾**：是否需要接入 reCAPTCHA / Turnstile

### 需前端确认的技术决策

1. **框架选型**：Next.js（SSR/SSG）/ Nuxt / Astro / 纯 CSR，需结合 SEO 要求
2. **Markdown 编辑器**：推荐 Milkdown / ByteMD / Toast UI Editor，需评估集成成本
3. **Markdown 渲染**：推荐 `remark` + `rehype` 生态，需确认代码高亮方案（Shiki / Prism）
