# 分层上下文记忆

六个角色共用 `backend/app/agents/memory.py`。Leader 在调用模型前处理消息；Worker 的 LangGraph 使用独立 memory 节点先保存替换后的状态，再进入 agent 节点。工具本身无需接入压缩接口，新增工具的 `ToolMessage` 自动适用。

## 预算与三层处理

预算使用 `AgentSpec.context_window` 或 `QWEN_CONTEXT_WINDOW`（默认 131072），预留 25% 给输出和协议开销，再减去当前工具 schema。调用前用 UTF-8 字节长度估算消息与参数成本；这不是供应商的精确 tokenizer，也不用于计费统计。供应商仍报上下文超限时，额外进行一次干净上下文重试，持续超限不会无限循环。

1. **初级折叠**（`backend/app/agents/context_fold.py`，不调用模型，按“指针”而非删除处理）：
   - **按轮次保留**：最近 `WDRUNGE_FOLD_KEEP_ROUNDS`（默认 3）个模型轮次及其全部工具结果保持原文；当前轮次（含并行调用中尚未被模型读到的结果）永不折叠。
   - **被取代的结果**：同一文件、文档章节、目录、检索、进程状态或相同前台命令被再次读取/执行后，旧结果替换为一行存根，指向新结果的消息 ID；完整读取取代该文件的所有分段读取；`write_project_file` 成功后，该文件此前的读取标为“已过期”。当前轮次除外。
   - **按工具摘要**：更早的结果超过 600 字符时，按工具保留决策所需事实而非截取开头：命令保留 argv、退出码、错误/警告行和末尾几行；`browser_verify` 保留 passed、断言结果、错误样例和截图路径；`read_project_file` 保留路径、sha256、行数和下一页 offset；协作文档保留文档/版本/章节标题；其他 JSON 保留结构化缩略；无法识别的文本才截取开头。写入文件的正文参数替换为长度和 sha256 前缀（文件在磁盘上）。
   - **任务台账**：在折叠边界插入一条台账消息（`additional_kwargs.context_ledger`），记录已写/已读文件及哈希、共享文档版本、后台进程与端口、已执行命令的最近退出码、浏览器验证结果、尚未解决的工具失败（之后同一目标成功即移除）。内容不变时复用同一消息，不破坏缓存。
   - **折叠的调用参数不能当值回传**：写文件的正文、过长的参数折叠后留在历史调用里，形式与真实参数相同，模型可能照抄进新调用。占位符带有“不是原值”的说明，Leader 和成员执行任何工具前都会检查参数，发现折叠占位符即拒绝（`folded_placeholder`），不会写进文件或文档。
   - **找回原文**：每个折叠标记和存根都给出消息 ID，`recall_context(message_id, offset, limit)` 从压缩审计中返回该消息的原始内容（限本线程作用域），代替重新执行工具或重读未变的文件。
   - **缓存友好**：只有可回收的估算 token 达到 `WDRUNGE_FOLD_TRIGGER_TOKENS`（默认 12000）或超出预算时才成批折叠，一次折叠到保留轮次之前，减少改写历史前缀导致的提示缓存失效。

专业成员只绑定常用协作工具；订阅、检索、差异、历史、排期、依赖、快照、决策、维护、交接和 `create_task` 需先调用 `enable_tools` 启用，之后才出现在模型的工具列表中（执行层始终可调用）。Leader 仍绑定全部协作工具。用量记录保存供应商返回的缓存命中 token，工作日志在“累计使用”下显示缓存命中率（仅统计返回了缓存数据的调用）。
2. **历史摘要**：折叠后仍超预算时，使用当前历史作为摘要来源，将每项工具结果限制到 3000 字符（含截断标记），剔除运行时标记 `reissuable_reminder` 的提醒。最近一条任务/用户输入及最近的保留轮次保持原文；其之前的历史与其之后、保留轮次之前的工作分别摘要（摘要放在该输入之前/之后）。台账原样保留并提供给摘要模型以免重复；摘要按“目标与约束、决策、文件与产物、验证证据、未解决错误、下一步”组织。用户自行输入类似 reminder 的文字不会被误删。
3. **干净上下文接续**：当前工作轮次仍过大时，对整个工作状态生成交接，仅保留系统指令、台账和交接摘要。任务身份、权限、工作区和协作状态不变。`checkpoint_context` 同样保留台账。

摘要输入先分块再归并，单个超大用户消息或工具参数同样会切块，摘要调用没有工具权限。摘要的 token 用量计入角色累计用量。空摘要、被输出上限截断的摘要、无收敛的归并或 API 故障会保留原历史并报告失败，不会静默丢弃任务。

## 主动选择上下文

所有角色都可单独调用 `checkpoint_context`，提供结构化交接后在干净上下文继续当前工作。混合调用其他工具时会返回错误，防止重置破坏尚未处理的工具调用。

协作任务重试以 `fresh` 启动时，上一轮线程的台账（写过的文件、验证结果、进程、未解决失败）会追加到新一轮的 handoff，避免重做已完成的工作；上一轮的进程已在结束时停止。

委派仍支持 `fresh`、`continue`、`auto`：`fresh` 为新任务提供自足 handoff；`continue` 接续已有会话；`auto` 接续已有会话并交由分层压缩管理，不再达到 60% 就直接丢弃旧上下文。上下文清理不会隐式提交、完成、取消或新建任务。后台调度的任务生命周期继续由原调度器管理。

压缩使文件正文离开上下文时，会更新文档读取上下文 ID，允许重新读取相同修订；不会把未处理的 inbox 提醒自动确认已读。

## 持久化与可追溯性

- `context_compactions` 保存角色、作用域、压缩阶段、原消息 ID 区间、源消息、替换消息和压缩前后估算长度。折叠记录只保存被替换、移除或新增的消息；某消息首次出现的记录即其原文，供 `recall_context` 查找。原聊天记录不修改。
- `context_memory` 保存 Leader 的模型历史视图与外部聊天历史截止位置。重启后加载压缩视图，再追加截止点之后的消息。
- Worker 使用 LangGraph 持久检查点保存替换后的消息列表。替换使用 `RemoveMessage(REMOVE_ALL_MESSAGES)`，避免旧历史被消息 reducer 重新追加。
- `agent_usage` 按成功取得的供应商 usage 记录每次六个角色模型调用（含摘要）的真实累计 token。启动时聚合恢复；后台临时实例只贡献自身新增用量，避免重复加载角色历史总量。
- migration `0004_context_memory` 和启动时 `metadata.create_all` 均支持旧数据库添加新表。用户执行“清除所有记录”时同步清空。

历史版本未记录的用量无法可靠倒推。未收到供应商 usage 的请求不伪造计费数；标题模型及工具审核模型不在六角色统计口径内。
