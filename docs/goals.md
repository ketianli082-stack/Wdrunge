# Goal 与长期任务

Goal 把用户授权的多步目标、验收条件与 Task 关联起来。Task 复用已有的
SQLite 持久化协作请求、独立工作区、依赖图、执行租约与重试队列，不另建一套执行器。
普通一次性问答不需要创建 Goal。

## 工具

| 工具 | 用途 |
| --- | --- |
| `create_goal` | Leader 创建目标，提供 objective、criteria、稳定的 key；默认每 180 秒检查 |
| `create_task` | 为目标创建异步任务，提供 goal_id、recipient、goal、criteria、key，可指定 dependencies、artifacts 和 based_on |
| `get_goal` | 读取目标、完整验收条件及证据、任务统计和分页预览 |
| `submit_task` | 执行者提交交付，发布当前工作区后进入 review |
| `complete_task` | 委派者或 Leader 检查交付后验收，evidence 必须逐项覆盖任务条件 |
| `update_goal` | Leader 暂停、恢复、阻塞或取消目标，必须给出 reason |
| `complete_goal` | Leader 在全部 Task 验收后，提供逐项目标证据并关闭目标 |

`criteria` 为 1–8 个不重复的非空字符串，每项最多 300 字符。`evidence` 是以
完整条件文字为键、具体检查结果为值的对象。系统检查证据完整性；证据是否真实、
是否满足要求仍由执行者和验收者根据文件与测试确认，字符串本身不构成自动验证。
直接调用旧的 `collaboration_transition` 也不能绕过目标任务的验收条件。
Worker 通过旧协作工具派生的子任务自动继承所属 Goal。

Goal key 在项目内按 conversation 隔离；Task key 延用请求的项目/发送者范围。
重试同一创建调用必须使用原 key 和相同参数，避免丢失响应时重复创建。
目标最多允许每段对话 4 个未结束 Goal；已有任务并发与数量上限继续生效。
任务依赖必须属于同一 Goal。取消的任务不算完成，因此应取消其目标并重新规划，
而不是把未交付工作计入目标成功。失败任务可通过 `collaboration_transition`
重排原任务，保留工作区。

## Reminder 与恢复

每次模型调用前，从数据库生成有大小上限的 Goal reminder。它带有运行时 reminder
标记，不写入历史，也不影响协作消息回执；上下文压缩或溢出清理之后会重新生成。
`get_goal` 支持 offset/limit 分页（默认 10，最多 20 个任务）；任务详情通过
`collaboration_inspect_request` 读取，避免大量历史交付挤占上下文。`collaboration_snapshot` 可列出本对话目标 ID。

调度器每 10 秒维护一次持久化提醒时间；间隔可设为 60–86400 秒。
没有任务、待验收、失败或明确阻塞、任务已完成但 Goal 未关闭时，提醒通过持久化
事件收件箱唤醒 Leader。正常排队和执行不触发付费轮询。
连续无进展提醒采用 1、2、4 倍间隔退避；三次提醒后的下一次检查仍无进展，
则将 Goal 设为 blocked 并在群聊和目标面板报告原因。需要显式恢复才继续。
尚未被 Leader 处理确认的提醒不会重复入队，也不消耗无进展次数。
事件与下一次检查时间在同一事务中写入。重启后仅恢复记录，任务挂起，等待用户手动继续。暂停/恢复使用提醒代次，
不会重放暂停前的旧提醒。完成、取消、暂停、阻塞均停止自动提醒。

暂停或阻塞 Goal 会撤销正在运行任务的租约，停止执行并保留工作区；恢复后继续排队。
取消会终止未完成任务。旧执行实例不能提交或覆盖恢复后的新实例结果。
模型单轮结束、上下文 checkpoint、定时提醒本身均不代表任务或目标完成。

后台服务必须运行才能执行任务和发送提醒；关闭应用或机器休眠期间不会运行。
服务重启或应用重新打开时，未完成任务和目标统一挂起；不会自动处理到期提醒或继续旧任务。
只有点击当前对话的“继续任务”才恢复它的未完成工作，其他会话保持挂起。发送新消息不会自动释放重启前的旧任务。
这里不依赖操作系统通知或外部云调度。

## 界面与 API

“任务与协作”提供目标创建、进度、逐项验收、暂停、恢复、取消和阻塞原因。
上述工具也可通过项目 `/collaboration/commands` 调用：action 使用工具原名，
payload 使用相同参数，conversation 必须指向目标所在对话。
目标记录位于现有 `collaboration_records` 的 `kind=goal`，无需新增数据库表。

验证：`backend/.venv/bin/python -m pytest`（从 backend 目录使用 `.venv/bin/python`）。
`test_goals.py` 覆盖持久化、验收约束、租约、提醒、压缩恢复与后台协调完整流程；
`test_goal_ui.py` 使用已构建前端和可选 Playwright Chromium 检查界面交互。

## 对话停止与应用重启

输入框的停止按钮读取后端的对话执行状态，不依赖当前 SSE 连接。切换工作日志、
对话或页面后，仍可停止当前会话的生成、排队任务、运行进程和目标提醒。
停止接口先持久化禁止继续调度的状态，随后取消 Leader/Worker 并等待进程清理完成；
请求断开也不会中止取消操作。已完成交付和项目文件保留，其他对话不受影响。

重启恢复与停止不同：重启保留未完成任务，挂起等待手动继续；停止则取消未完成任务。
桌面窗口与后端可独立运行，因此前端在关闭页面时尝试挂起任务，重新打开时在加载历史
之前也会完成一次挂起确认；后端自身启动同样默认挂起旧任务。

API：`GET /api/conversations/{id}/execution` 查询状态，`POST .../execution/stop`
停止，`POST .../execution/resume` 手动继续；`POST /api/execution/pause` 用于应用
关闭/重新打开时挂起旧执行。仅恢复所选对话不会让其他会话自动继续。
